# 复盘：萧何（dsh-execution-bus）为什么没有成为“更优的 PTC 模式”

> **后续（2026-10）**：项目已按新方向改造为 **1.0 声明式运行时**（`runtime_run`）；下文的 0.x 结论仍成立——原“执行总线模式”不再维护，0.12.1 是最后的总线版本，本文保留为历史复盘。

> 结论先行：作为“通用 PTC 更优模式”的产品假设**未被证据支持**；0.x 执行总线冻结于 **0.12.1**，不再做功能发版。本文记录做了什么、被证伪了什么、留下了什么、以及什么条件下才值得重启（该条件促成了 1.0 的运行时方向）。

## 一、做了什么

从 0.7.0 到 0.12.1，项目实现了：会话级有界总线（并发/队列/记录/结果字节/保留期）、按会话轮转与类别优先级+老化的调度、Handler 舱壁与文件资源键互斥、requestId 去重与终态复用、PTC 预算到期后的分离等待（宿主 Job 投影 + 同 requestId 取回）、宿主工具 Handler（read/glob/grep/edit/write/pwsh/test）、预设派生与模式入口、简化调用 + 类型化 schema、只读会话诊断与采用率统计，以及四矩阵 CI 与逐字节发布门禁。

工程上是扎实的：**128 项测试**全绿，真实 Node PTC 验证了预算分离与外部中断，发布链路对 npm/GitHub 制品做了逐字节一致校验。

## 二、被证伪的核心假设

| 假设 | 证据 | 结论 |
|---|---|---|
| “总线让日常任务更快/更优” | 3 任务×2 臂 A/B：普通任务两臂 6/6 成功、**0 次总线调用**、耗时无一致差异 | 普通任务上≈PTC，无增益 |
| “默认引导走总线更好” | 指引级 A/B：总线优先 18 次调用 vs 可选 11 次；一次性长命令 106.3s vs 71s（含约 19s 排队延迟） | 总线优先是负收益 |
| “payload 去重能省重复执行” | 0.12.0 内置 host.* 去重导致陈旧读（read→write→read 返回旧内容），已回滚 | 需要 cwd/内容版本/失效模型，裸去重有害 |
| “存在真实用户需求” | npm 周/月下载 1094（旧版本各 130–156、新版本低，像镜像抓取）；GitHub 0 star/0 fork/0 issue、14 天 11 次浏览 1 访客；本地 156 会话仅 11 用过总线（多为 pilot/审查） | 无外部采用 |

## 三、根因

1. **定位错误**：把“执行协调层”包装成“可选模式/更优模式”。协调收益是**条件性**的（重复/重试、跨预算、多等待者、共享容量/资源锁），不是通用增益。
2. **没有绝对优势**：原生 PTC + 后台 Job（run_in_background + job_output）已覆盖大部分长任务；总线只多出“统一快照 + 复用语义”，且纯内存、重启即失、无真取消/持久化。
3. **宿主契约脆弱**：依赖私有中断原因字符串 run_code settled、单实例、无持久化/跨进程接口；升级即可能破坏核心语义。
4. **需求池太小**：DSH 插件生态本身很小，且没有暴露“多 Agent 共享执行/持久化 exactly-once”这类总线能赢、原生给不了的需求。

## 四、仍可复用的资产

- **PTC 预算分离机制**：run_code settled → 只停止等待、执行继续、宿主 Job 保留（见 [宿主兼容性](<host-compatibility.md>)）。
- **宿主 Job 投影 / ExecutionOwner**：把 core completion、取消、Job 生命周期和工具交付统一管理。
- **预设代际（generation）作用域**：插件实例按预设修订共享，跨会话共享容量/资源锁。
- **幂等/去重语义与陷阱**：requestId 冲突、终态复用、reused:true、payload 去重需失效模型。
- **工程方法**：128 测试、四矩阵 CI、逐字节发布门禁、证据导向的 A/B 与 pilot——这些比代码更可迁移。

## 五、什么条件才值得重启

- 出现**真实用户报告**的“原生工具解决不了”的需求：多 Agent 共享同一次长执行、跨重启的 exactly-once 副作用、跨进程资源串行。
- 宿主开放**持久化/真取消/稳定中断契约**，使插件能做出原生做不到的保证。
- 或把 core 泛化为 **host-agnostic 的持久执行层**（另一个项目，而不是继续修模式层）。

## 六、归档处置

- 冻结于 0.12.1，不再发功能版；仓库保留作参考实现。
- 不推荐新项目采用；若误装，请改用原生工具与后台 Job。历史发布说明与证据见 [0.12.1 发布说明](<releases/0.12.1.md>) 与 [验证记录](<validation.md>)。
- npm 已无进一步发布；如需对已发布版本加弃用说明，可在已登录的 npm 环境执行：
