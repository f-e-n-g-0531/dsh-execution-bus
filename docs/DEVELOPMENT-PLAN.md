# 研发计划与验收门禁

## 基线与边界

已发布研发基线为 v1.2.2（提交 `4c526cf`），当前源码目标为 minor 版本 v1.3.0；目标宿主 DSH 0.2.1-rc.5、Cordis ~4.0.5、include ~1.0.10、Node ≥22。v1.2.0/rc.2 的历史验证不移作新候选证据。v1.3.0 的交付须待实现、复核和门禁结果确定，本文不表示该版本已发布。

本计划把实现、组件回归、真实环境验收和收益实验分开。组件通过不能替代真实模型、桌面 UI、实际 OS 沙箱或整宿主生命周期验收；缺少条件或证据的项目保持 pending，不补成功样本。具体验收步骤见[流程测试](<FLOW-TEST.md>)，证据边界见[验证范围](<validation.md>)。

不修改日常 DSH 的配置、安装或运行状态，不读取或复制凭据，不自动安装、重启或启动服务器。当前尚无已确认的隔离目标；研发授权不扩大为日常 DSH 的破坏性操作授权。环境准备及生命周期实验先确认专用隔离宿主，再另行执行。功能兼容与[上游依赖安全风险](<host-compatibility.md#依赖安全告警>)独立判断，不能相互抵销。

## 阶段 1：固定基线与隔离真实验收

**目标：** 将候选字节、宿主契约及真实环境证据绑定，先明确尚未证明的能力。

- 对同一源码快照执行组件检查、包白名单及生产依赖安装 smoke，记录实际通过、失败、跳过和候选 SHA-256。生产安装 smoke 使用 stub host，不将其登记为真实桌面验收。
- 确认独立 profile/配置、数据、运行记录、工作区、会话、真实 OS sandbox provider 与可中断的专用宿主；精确记录宿主/模型 ID 和非敏感权限配置标识，不检查 token。
- 在隔离目标 GUI 和实际模型链验证派生预设、普通 Agent 隔离、PTC 整链、read-only/workspace-write、审批拒绝、取消/async、scope 卸载、整宿主重启、unknown 副作用核对及后台 Job 清理。按候选绑定的十二项账本逐项保存时间、断言和受控 evidenceId。
- 缺少隔离条件、模型可用性或人工操作条件时，只完成前置核查与 pending 账本，不触碰日常环境，不把其他候选的证据挪用为 pass。

**验收：** 组件结果与真实十二项分别披露；只有真实执行并具备完整环境、起止时间、全部断言与对应证据的条目才可登记 pass。离线账本校验通过仅证明报告完整与候选匹配，不独立认证断言。上游安全告警独立记录与评估。

**当前证据状态：** 真实十二项尚未验收，保持 pending；只读核查不证明隔离宿主已经配置或可用。

## 阶段 2：减少历史记录的重复扫描

**目标：** 在不改变公开行为的前提下，减少历史记录重复读取、解析和扫描；metadata/缓存只作可重建的派生 hint，记录文件仍是事实源，不另造存储真相。

约束与回归要求：

- 不改变 checkpoint 次序、落盘失败停止调度、同步接口或执行器/服务语义，不移除单步状态保存。
- 保持 owner 先过滤再分页，保持 updatedAt/runId 排序；prune 仅保留最新 100 条终态并保护 running/interrupted，不因旧 hint 误删可恢复记录。
- load 仍须通过文件句柄重新 fstat 验证身份、大小、mtime/ctime；外部替换、同大小改写、损坏或删除必须失效重读。缓存丢失可重建，不得泄露其他 owner 的记录，不得以缓存命中绕过完整校验。
- 用确定性用例比较优化前后可观察结果，并覆盖缓存失效、owner 变更、分页、排序、坏记录诊断及 prune 保护。真实 fork/crash 和真实 pwsh 回归继续保留，不用纯缓存测试取代。

**验收：** 先通过一致性与安全回归，再用相同数据规模、recoverable 比例和重复采样口径比较新实例首次 list、同实例 warm-list、prune、服务启动耗时与事件循环探针；前两项不代表 OS 缓存冷/暖实验。披露准备时间、样本和缺失数据；若安全性无法保证，采用保守失效/重读，不以命中率换安全边界。没有测量结果不写优化比例，组件容量改善不推导模型收益。

## 阶段 3：小规模真实模型对照

**建议规模：** 固定一个精确模型，只读（read-only）、混合读写（mixed）、故障恢复（recovery）三类，每类两个任务，各重复三次，native/runtime 两臂，共 36 次任务尝试（18 对）；这是建议样本方案，不是工具强制门槛。输入快照、任务成功判据与最终样本方案在实验前固定，不依结果临时挑选。任务类别可与[流程测试的 pilot 口径](<FLOW-TEST.md#小范围收益对照试验待真实-pilot>)对齐。

- 复用既有 pilot 收集/报告与容量基准，补充最小严格 manifest，不另建统计系统。manifest 绑定候选 SHA-256、精确宿主和模型 ID、native/PTC 模式、sandbox、输入快照标识、两臂相同并发预算与配对执行顺序。
- 对照臂使用原生工具及原生并行能力，不以串行弱基线制造收益。固定并平衡配对顺序；两臂使用相同资源、重复次数和任务成功标准。
- 记录端到端耗时、模型轮次、工具请求/成功数、人工介入和可取得的 token 指标；纳入准备、轮询、重试和恢复成本。保留 failed/aborted/cancelled/interrupted/unknown，不只收集成功样本；缺失指标保持缺失，不填零。
- 故障恢复任务另核对实际副作用、成功步骤重放数、unknown 和停止后新增步骤数。runtime succeeded 不是任务成功，unknown 不是副作用未发生。
- 条件不可用时仅交付可校验的实验 manifest、待采集清单与执行方案，不调用模型、不生成尝试或成功数据，不宣称收益。

**验收：** 按预登记样本方案完成可追溯且口径一致的实际尝试，采用建议方案时为 36 次，报告全部 outcome 和缺失覆盖；配对差值需满足同任务/快照/环境/并发且两边成功，并同时披露失败配对。未完成真实 pilot 前，只可声明工具准备情况，不能声明效率、成本或可靠性提升。

## 阶段 4：只读补位调度（条件阶段，当前不实施）

只有真实对照证据证明批次屏障是主要可改善成本，且收益覆盖新增复杂度后，才评审只读补位调度。即使通过评审，也须显式启用，不能静默改变现有批次语义；须独立证明依赖、并发上限、取消、恢复和写副作用边界不退化。没有真实收益证据，本阶段保持延期，不扩大本次实现范围。

## 条件延期范围

| 能力 | 进入下一次设计的条件 | 当前边界 |
|---|---|---|
| 跨进程/分布式执行 | 真实需求与执行所有权、协调和恢复协议明确 | 不作为本次交付，运行时仍随宿主进程退出 |
| 断电刷盘保障 | 明确持久性需求及 fsync/平台故障实验成本 | 不将原子写或进程 kill 测试宣传为断电持久性 |
| 大结果与制品管理 | 实际负载证明当前结果上限成为瓶颈 | 不扩展结果存储协议或搬入制品系统 |
| 独立运行看板 | 实际使用与处置需求明确，宿主展示仍不足 | 不另建服务器、状态中心或遥测系统 |
| 动态分支 | 真实任务证明固定 DAG 不足，语义与安全预算明确 | 不引入动态工作流语言或隐式副作用重试 |

## 合入与发布检查

主代理统一复核差异、构建、执行全量检查和候选包验证；各阶段分别报告完成、未执行与 pending，不把规划写成已完成。发布与标签按[发布流程](<RELEASING.md>)另行执行，文档计划或组件通过不构成发布授权，更不自动安装或重启 DSH。
