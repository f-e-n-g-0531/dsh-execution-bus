# 产品结构与维护契约

## 产品边界

萧何是 DSH 内的可选执行协调插件，提供独立可选择的 PTC 派生预设，不是 PTC 替代传输层，也不全局接管终端、编辑或其他工具。实际业务 Handler 为 host.read；test 是兼容保留的诊断 Handler，只有明确诊断需求时使用。测试能力存在不代表其他命令已接入总线。

0.5.1 按正式产品梳理入口和共享策略，不以更名宣称完成生产环境认证。当前真实模型、桌面 UI 和实际沙箱尚未完整验收；同进程内存状态不支持跨重启恢复。

## 入口及配置层次

| 入口 | 谁使用 | 责任 |
|---|---|---|
| 包级 bundle /preset | 目标 DSH 配置加载器 | 读取 ptc 声明快照，注册独立萧何预设 |
| Agent 内 /mode | 萧何预设末尾插件行 | 保留原 PTC 组合，追加总线工具和说明 |
| /test-mode | 旧配置兼容 | 直接映射同一个正式 mode 模块，不维护第二份实现 |
| 包根入口 | 明确自行组装的宿主 | 注册 execution_bus、execution_bus_state，不派生 PTC |
| /core | 可信嵌入方 | 自行注册 Handler 的内存核心，不提供外部身份认证 |

正式代码在 src/mode.ts，src/test-mode.ts 只重导出。package exports 的新旧入口均映射 dist/mode.js，避免 Cordis 因插件模块身份不同而重复激活；旧物理构建文件仍兼容重导出。不要同时配置两行别名。预设 ID execution-bus-test 和配置行 ID preset-execution-bus-test 是历史兼容身份，不继续用于推荐显示名称。

## 模块职责

| 模块 | 负责 | 不负责 |
|---|---|---|
| product | 固定身份、容量/准入默认值、工具参数与提示契约 | 不提供用户可覆盖的运行时配置入口 |
| preset | 声明派生、兼容检查和宿主注册 | 不偷偷重写源 ptc 或持久配置 |
| mode / test-mode 兼容层 | 作用域说明与工具安装 | 不改宿主权限/沙箱/呈现，不加载第二套 PTC |
| plugin | 工具身份校验、可信执行上下文和宿主 read 派发 | 不自行文件读取或创建通用命令执行端 |
| bus / json | 请求校验、幂等冲突、调度、取消、终态与有界状态 | 不以超时推定副作用失败、不自动重跑 |
| execution | Job 投影、活跃工具交付与关闭所有权 | 不作为第二个执行状态机 |
| handlers | 实际读取适配和明确诊断 Handler | 不把测试当成通用业务执行 |
| diagnostics | 有界数值轨迹 | 不保留请求内容、错误原文或充当授权审计 |

## 兼容和错误规则

稳定工具名、请求协议和历史预设身份保留。协议校验/背压错误与执行快照中的固定错误码分层；宿主服务错误继续保持真实失败，不统一吞掉，也不把 error 文本写入数值诊断。完整错误词汇见协议说明，本轮不重命名既有错误码。

单一策略定义不表示开放 YAML 调参：宿主插件目前使用固定默认值；core 构造参数仍按原契约使用。新增配置界面需单独定义校验、升级与误配置回归，不能只在文档放不存在的 config 键。

## 交付要求

- 修改身份、默认策略或工具提示时，验证共享 product 契约与实际宿主状态工具一致。
- 新旧 mode 必须指向同一个模块，派生预设必须使用正式入口。
- 严格包白名单覆盖正式模块、兼容转发与类型文件；生产隔离安装通过包导出导入两入口核对身份。
- 继续全量 core、真实宿主生命周期及 Node PTC 回归，不用文档测试替代桌面验收。
- 完整验证后统一标签 CI 和正式发布；发布不自动安装/重启日常 DSH。
