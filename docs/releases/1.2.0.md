# 萧何 / Xiao He 1.2.0

本版补齐 PTC 调用链验证、运行进度与故障处置提示，并提供离线验收及对照试验工具。正式发布遵循同标签四矩阵 CI 与公开制品核验流程；发布不会自动安装、升级或重启日常 DSH。

## 使用与故障处置

- 在保留五个 runtime_* 工具、六种叶子工具和 version 1 记录格式的基础上，增加运行进度与安全处置提示，区分停止调度和工具实际停止，不自动重放未知副作用或接管后台 Job。
- 提供[运行状态与故障处置](<../OPERATIONS.md>)，覆盖 unknown 核对、Job 收集停止、存储失败、敏感记录目录与长期中断记录。
- 随包提供离线验收账本、pilot 对照报告和容量/长尾基准工具；用途和命令见[流程测试](<../FLOW-TEST.md>)。账本不证明操作者断言真实性，组件基准不代表模型成本收益。

## 集成与兼容

- 补充实际 Node PTC 子进程通过 run_code 调用运行时、再嵌套调用宿主工具的自动化测试；权限拒绝夹具不等于实际沙箱。
- 扩充预设启动、等待失败和派生边界回归；继续保留宿主组合、disabled 与表达式声明，不求值表达式，不修改默认预设。
- 批次调度、单步结果 64KiB、计划 32 步/64KiB、并发 1–4、进程内 8 active 的限制不变。不增加跨进程锁、断电事务、动态分支或大结果制品 API。

## 验证边界

本地 Windows / Node 24.21.0 的 142 项自动化测试全部通过、无跳过；包白名单和同一候选纯生产依赖安装检查通过。正式标签四矩阵 CI 与公开制品核验结果以对应 Actions 记录为准，不预写 CI、桌面或模型通过。真实模型/桌面 UI/实际沙箱、完整宿主桌面重启及真实收益对照仍需隔离验收；新增工具把这些待验收项显式记录为 pending，不会把桩或 skipped 当作通过。

容量组件单次基线显示：1万条历史下查询约1.9–8.0秒、启动约6.9–51.8秒，存在同步磁盘扫描阻塞。测量与其他开发负载有重叠，不是稳定 SLA，也不是正式候选的跨平台性能认证；本版提供测量工具但未实现异步存储、索引或动态补位调度。对大量历史或长期中断记录的部署应先做本机容量验收。
