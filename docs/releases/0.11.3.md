# 萧何 / Xiao He 0.11.3

## 证据补记：收益导向 vs 总线优先 A/B 对照

本版只补记验证证据与文档，不改变行为、协议或提示。

- **背景**：0.11.0 起默认采用收益导向触发。为验证“总线优先”是否值得作为第二预设，用同一版本（0.11.2）、同一模型、同一组 5 类任务、各 5 个全新子代理会话做**指引级对照**：A 臂=当前可选触发，B 臂=在任务前加“超过约 10 秒或需跨步骤就优先走总线”的总线优先指引。
- **结果（来自会话日志统计）**：

| 任务 | A 臂（可选/收益导向） | B 臂（总线优先） |
|---|---|---|
| 一次性 40s 长命令 | 0/2 用总线（直接 pwsh，40.9s） | 1/1 用总线（多一层包装，无协调收益） |
| 70s 跨预算取回 | 2/2 用总线（约 71s） | 1/1 用总线（106.3s，含约 19s 排队延迟） |
| 45s 跨步骤 | 1 用总线分离重附着、1 用宿主后台 Job | 1/1 用总线（4 次调用） |
| 普通 grep 快任务 | 0/2 用总线 | 0/1 用总线 |
| 同一逻辑重复提交 | 1/1 用总线，2 次 reused:true | 1/1 用总线，3 次 reused:true |

  总线调用总数：A 臂 11 次 / 5 会话；B 臂 18 次 / 5 会话。

- **结论**：收益导向的可选触发是更好的默认；总线优先会提高采用率，但提升部分主要是一次性长命令等无收益场景，并可能因总线并发/排队增加延迟。因此不把 bus-first 作为默认，也暂不发布为正式第二预设。
- **边界**：这是指引级对照（非预设级）；并发子代理、单机、小样本，非统计显著；轮次/耗时/成功率的大样本 A/B 仍未完成。预设级对照需要 GUI 手工创建两种预设的会话，本轮未做。
- 附带验证了幂等契约：只读 Handler 终态复用返回 reused:true（毫秒级）、有副作用 Handler 终态重发返回 MUTATING_REUSE_DENIED、同 requestId 换参数 REQUEST_CONFLICT、新 requestId 才重新执行。
