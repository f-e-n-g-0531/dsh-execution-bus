# 萧何 / Xiao He 0.12.1

## 0.12.0 行为风险热修

本版修正 0.12.0 默认 payload 去重导致的数据正确性问题，并处理同轮审查发现的高优先级调度/生命周期/文档缺陷。**wire 协议与工具调用形状不变。**

## 修正

- **关闭内置 host.* 的 payload 去重**：0.12.0 给 `host.read`/`host.glob`/`host.grep` 默认声明了 `dedupe:"payload"`。文件被编辑、会话切换工作目录或权限变化后，同输入的新 requestId 会静默返回旧内容（现场已复现：read 记 v1 → write 改 v2 → 再 read 仍返回 v1）。0.12.1 起内置 Handler 不再声明该能力，恢复“相同参数的新 requestId 是新操作”；核心 `Handler.dedupe` 能力保留，扩展 Handler 如声明须自行承担失效责任。
- **等待老化不封顶**：原 `boost=min(2,...)` 削不平 default(3) 与 fs(0) 的差距，持续 fs 负载下 default 类可饥饿/必超时；改为按等待时间持续提升、最低到 0，同分按 FIFO。
- **唯一复用记录计入保留字节与时间戳**：`syntheticUnique` 深拷贝结果但 `resultBytes=0`，且无 startedAt/finishedAt 导致 `queueMs` 随保留期增长；现按结果字节计入、写入时间戳，sweep/close 正常递减。
- **waitReason 区分舱壁与资源**：新增 `bulkhead`，不再把 Handler.maxConcurrency 等待误报为 `resource`。
- **注册时校验并快照 Handler 选项**：校验 run/validate 为函数、idempotent 严格布尔、queue/dedupe 合法；冻结调度字段并拒绝 `__proto__` 等类名，避免运行期篡改、NaN 优先级和永不调度；scheduler 策略拒绝 accessor 与原型污染键，数值只读取一次后校验。
- **关闭重入**：validate/resources 同步执行中触发 `close()` 后不再向已关闭总线插入永不结算的记录，改为拒绝准入（CLOSED）。
- **消息身份改存 SHA-256 摘要**：同一 requestId 多条消息不再保存完整 canonical 文本，避免消息额度内无字节上限的内存放大；冲突检测语义等价。
- **文档修正**：protocol 恢复“新 requestId 新操作”并补错误词汇表；validation 更新 PTC 预算参数（8s/12s）、资源互斥跨会话范围（同一预设修订共享，跨进程/跨代际不保证）、修正 0.12.0 发布说明中的范围表述；0.11.1 标注“未发布”；OPTIMIZATION 标注历史并链接当前实现；INTEGRATION 标题与老化说明同步。

## 验证

- 新增 6 项回归：default 类老化不饥饿、bulkhead/resource 等待原因、注册负例、scheduler accessor/原型污染、关闭重入、唯一复用字节/时间戳、资源锁失败/取消释放。
- 本地全量测试通过（122 + 6 = 128 项；以 `npm run check` 实际输出为准）。
- 未复制第三方源码、未新增运行依赖；fast-check 仍仅为 devDependency。

## 升级说明

需要 DSH 0.2.1-rc.2。工具名、wire 协议与既有错误码不变；行为变更仅影响内置 host.* 的 payload 去重（默认关闭）。旧版创建的总线实例/记录不迁移；重载或升级会创建新的预设修订，旧 requestId 不可取回。

## 验证与限制

调度与资源锁按预设修订共享总线实例，跨进程、跨代际、OS 级文件锁均不保证；资源键别名（相对/绝对、大小写）可能绕过互斥。真实模型、桌面 UI 与实际沙箱仍未完整验收。
