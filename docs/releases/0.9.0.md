# 萧何 / Xiao He 0.9.0

## PTC 预算到期后的分离等待

本版解决“长任务超出 `run_code` 时间预算就被连带取消”的问题：程序结束只停止等待，已受理执行继续。

- PTC 程序结束或 `run_code` 时间预算到期时，宿主会以固定原因中断其中的工具子调用。总线对已受理请求只解除本次等待：执行与宿主 Job 继续，同一会话可用同一 requestId 的 `status`/`result` 取回结果（受 1 小时保留期与 256 条记录上限约束），或发送 `cancel` 取消。
- 用户/会话主动中断、沙箱模式变化等其他中断原因仍请求取消整个执行；未知原因保守按取消处理。
- 该区分依赖 DSH 0.2.1-rc.2 实际使用的内部中断原因字符串（`@deepseek-ai/dsh-tools` 构建中的 `run_code settled`），不是宿主公开稳定契约；宿主升级后需复核。
- core 的 `submit()` 附着新增只读 `snapshot()`，供停止等待时返回当前快照；不改变既有状态机、幂等与结果保留语义。
- 模式提示与工具体描述同步说明取回与取消方式。

## 升级说明

需要 DSH 0.2.1-rc.2。行为变化：**PTC 程序结束不再连带取消已受理执行**。若需要旧行为（程序结束即取消），应在程序结束前显式发送 `cancel` 控制消息。不自动安装、重写日常配置或重启 DSH。历史预设、配置行、工具名、协议字段与既有错误码均不变；状态仍为进程内存，不支持跨重启恢复。

## 验证与限制

本地全量 101 项测试通过（新增 6 项分离等待回归、2 项真实 Node PTC 预算/中断回归，覆盖宿主 Job 生命周期、重附着与分离后的宿主工具续调用）。真实模型、桌面 UI 与实际沙箱仍未完整验收；分离等待只在同一插件实例存活期间有效，进程退出即丢失状态；跨宿主版本的中断原因识别未验证。
