## 3. 诊断与未插桩对照

- 复用已有容量基准、独立进程对照和调用归因工具，不新增遥测服务。源码仓库开发入口为 `dev/compare-capacity.mjs`、`dev/profile-capacity.mjs`；它们不随 npm 包分发，不能在安装包目录照搬调用。
- 冻结完整构建与测量依赖，记录 Node、平台、配置与摘要；采样时不同时构建、安装或运行测试。新进程不等于 OS 冷缓存或机器独占。
- 归因工具当前最多 1k 历史，查询固定单 owner／前 20 条；多 owner、深页或更大规模不在其现有代表范围内，不能直接外推。只在目标负载确有需要时扩展最小夹具。
- 诊断运行与未插桩计时分开。必要时测扫描校验、排序选页、页内权威重读、恢复保存及删除的明确窗口，避免重叠；未实现的阶段测量保持缺失。
- 同步 fs 包裹耗时可能嵌套，不能相加或从操作耗时相减推算 CPU／排他成本。API 调用数不是内核 syscall，比较次数不是耗时收益。

## 4. 决策规则

|判断|继续条件|不满足时|
|---|---|---|
|性能立项|实际预算已确认、代表负载超预算，且定位到可安全改变的主要成本|保留当前实现，不继续微优化|
|单项原型|只针对一个已证实瓶颈，预先固定对照与安全标准|不接 top-k，不删除权威读取或复验换收益|
|生产接入|独立未插桩对照达到预算；关键输入顺序、owner、深页无超阈值退化；失败率和内存符合预定标准；安全回归通过|丢弃或保留开发原型，允许结论为“保持现状”|
|真实验收|专用目标与操作范围确认，实际执行并有候选绑定的断言和证据|保持 pending，不用组件或账本校验代替|
|模型收益对照|相关真实验收通过、依赖风险独立评估，任务／模型／权限／预算预登记|只准备 manifest，不生成尝试或成功数据|
