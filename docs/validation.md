# 验证范围与使用限制

本文说明当前版本的证据边界，不是生产环境认证。当前能力基线为 **v0.11.1**，在 0.5.0 的会话准入/排队、0.7.0 的宿主工具转发、0.8.0 的搜索/命令 Handler、0.9.0 的预算分离等待与 0.10.0 的采用面改造上，收紧为收益导向触发并加入简化调用、复用标记与本地采用率统计；0.11.1 仅补充跨步骤取回的正确姿势说明；预设沿用 v0.3.0 的宿主 PTC 声明派生方式。验证环境为 Windows、Node.js 24.21.0，宿主组件锁定 DSH 0.2.1-rc.2、Cordis 4.0.4。

## 已验证什么？

| 层次 | 检查内容 | 能说明什么 |
|---|---|---|
| 总线核心 | 参数、队列、并发、重复请求、冲突、取消竞争、结果保存、TTL、监听与注销 | 程序内部约束及已覆盖异常路径可重复检查 |
| 真实宿主组件 | Cordis、ToolRuntime、LocalJobs、LocalFS、文件工具；host.glob/host.grep/host.pwsh 的转发测试使用宿主工具桩 | 请求经过真实工具管线；权限拒绝、Job 进度、共享任务、参数校验、幂等分流与清理逻辑有效；Agent 身份与工具实现为夹具，桩不证明真实搜索/命令工具实现 |
| 真实会话循环 | AgentLoop、AgentRegistry、SessionStore；脚本模型适配器 | 内存会话中原工具结果只提交一次，完成后再进入下一次适配器调用 |
| PTC 预算分离等待 | 真实 Node PTC `run_code` 以 2 秒预算等待 5 秒总线执行：预算到期后执行继续、宿主 Job 保留、同 requestId 取回结果；外部中断仍取消执行 | 在 DSH 0.2.1-rc.2 实际中断原因下成立；固定字符串不是跨版本契约 |
| 简化调用与复用标记 | 简化请求/控制、完整 v1 消息兼容、终态与运行中复用返回 `reused:true`、非法形状拒绝 | 组件级测试确认；不改变 wire 语义与副作用边界 |
| 预设隔离 | AgentPresetRegistry 与 Loader | 派生预设可激活；源 ptc 声明不变、普通 Agent 不可见总线；原 write/edit/Job 工具保留，宿主前置策略拒绝仍有效 |
| 故障注入 | 克隆失败、观察者拒绝、Job 等待/清理异常、先行移除与卸载交错 | 指定故障下的回归约束；不证明所有故障组合都已覆盖 |
| 候选包 | 严格文件白名单、临时目录生产依赖安装、入口注册 | 包可安装和加载；安装验证使用简化宿主夹具，不是桌面插件管理器验收 |

## 未验证或不支持

| 项目 | 当前结论 |
|---|---|
| 当前桌面真实模型发起请求并继续推理 | 未验收；脚本适配器不是实际模型 |
| 当前桌面预设卡片、进度界面、授权提示和实际沙箱 | 未验收；组件事件和 LocalFS 测试不等于桌面 UI/沙箱 |
| 实际模型/桌面 PTC 与时间预算、沙箱行为 | 真实 Node PTC 隔离子进程已调用原 read 和总线；使用显式 danger-full-access 测试策略与测试 Agent，不是桌面沙箱/真实模型验收 |
| 从真实 tgz 经宿主插件管理器加载预设、卸载与回滚 | 未完成完整桌面流程；源码工作区的 Loader 测试不能替代 |
| 真实 glob/grep/pwsh 工具实现 | 未在测试环境启用：真实搜索工具依赖打包 ripgrep 与 subprocess 服务，真实 pwsh 依赖 shell/sandbox/审批组合；本版只验证按 handler 名转发、输入校验、幂等分流与失败固定码 |
| 跨版本 PTC 中断原因 | 分离等待只识别 DSH 0.2.1-rc.2 实际使用的固定中断原因字符串；宿主升级后未知原因保守按取消处理，需复核 |
| 模式采用率与效果 | 未完成 A/B。0.10.0 pilot 显示采用面改造能让总线被真实使用（2/3 符合条件任务），但样本小、任务由本仓库构造；0.11.0 收益导向收紧后的采用率与轮次/耗时收益仍未知，需两臂复测，不能由 schema 或单元测试推断 |
| 磁盘会话结果提交及重启恢复原调用 | 未验收磁盘提交；本插件不支持跨重启恢复 |
| 减少真实模型轮次、状态查询或总耗时的对照 | 未验证，不给提升比例 |
| 长期运行、所有卸载/服务故障组合 | 未穷尽；持续故障仍有清理限制 |

## 需要知道的运行约束

1. 受理、队列、结果及交付标记均在内存。进程关闭会丢失，宿主会话日志不等于插件恢复执行权。
2. 同一预设的会话共享总线容量，已受理任务会话轮转、会话内 FIFO；结果访问按会话隔离，不是独立进程或资源安全隔离，也不保证入队名额公平。
3. 取消任一正在等待的重复调用会请求取消整个逻辑执行，不是仅停止该等待者。
4. 已终态且未过期的请求可直接复用结果，不申请新 Job；仍须通过身份、冲突及消息额度检查。
5. 等待服务异常后先排空原执行，再有界检查宿主记录；服务持续不可用时记录可能留到所属生命周期清理。不合作 Handler 仍可能阻碍关闭。
6. `returned` 不是宿主持久化或模型消费确认；外层取消和后置策略仍可能改变最终工具结果。
