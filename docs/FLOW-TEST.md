# 不安装到日常 DSH 的流程测试

## 适合什么场景？

先验证代码行为，而不改日常 DSH 配置。命令在独立 Node 进程中加载本仓库产物和真实 DSH npm 组件，不向正在使用的宿主注入插件，也不重启宿主。

**由聊天会话启动测试，不等于该聊天会话直接调用了 execution_bus。** 真实模型、GUI、PTC 进程和桌面沙箱结论不能由此替代。

## 如何运行

```powershell
npm ci --include=dev --ignore-scripts
npm run test:flow
npm run check
npm run verify:package
npm run test:install
```

| 命令 | 实际范围 |
|---|---|
| `test:flow` | 三个固定测试文件：早期流程回归、真实宿主工具组件、脚本适配器驱动的 AgentLoop |
| `check` | 编译并运行全部测试；包括后续 Job 故障、卸载、预设隔离等回归 |
| `verify:package` | 检查候选打包清单及导出，不安装日常宿主 |
| `test:install` | 在临时目录安装生产依赖并验证根入口/简化注册，结束后清理 |

`test:flow` 不是全部集成测试的别名；发布前必须运行 `check`。临时安装不是桌面插件管理器安装。完整验证层次见[验证范围](<validation.md>)。

## 已覆盖的代表场景

- 正常受理与异步返回，两个会话不串线，同键冲突拒绝。
- 并发重复请求共用执行/Job；终态结果在宿主槽位满时仍可复用。
- 查询额度、附着容量、取消保留槽及过期结果清理。
- 合作取消、晚取消、未知结果不自动重跑。
- 深层/非 JSON 结果拒绝，结果和通知不可变，异步观察者拒绝隔离。
- 已受理 Handler 与替换注册并存，旧注销函数不破坏新注册。
- 宿主 read 真正经过工具管线；前置拒绝仍生效。
- Job 先行移除、等待/清理异常与卸载交错。
- 派生预设成功激活、原 ptc 声明不变、普通 Agent 不可见总线、write/edit 保留且宿主策略可拒绝。
- 真实 Node PTC 进程调用原 read 与总线；测试使用显式非约束策略，不代表桌面沙箱通过。

以上是场景摘要，不表示真实模型/宿主 GUI 已通过。

## 测试之外仍需注意

- 宿主 read 的错误目前被适配层统一映射为 `HOST_READ_FAILED`；在取消后可能保守记为 `unknown`，不能把它当作取消已确认。
- 相同逻辑请求的取消是请求级取消，不能简单用 Promise.race 放弃执行来改成等待者级取消。
- 当前没有远端 Handler 传输或持久化恢复；测试没有提供这些能力。

## 要直接在聊天会话中试用

需要先通过宿主正常加载插件，并让目标 Agent 看得到 `execution_bus`。建议加载可选“萧何”预设，新建专门会话；不要全局注入工具。安装/加载需使用者自行授权，是否重启由使用者决定。只启动另一个 Node 进程、伪造 sessionId 或追加聊天结果，都不算恢复原工具调用。参见[使用说明](<../README.md>)。
