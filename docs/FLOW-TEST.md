# 不安装插件的流程测试

## 本次执行方式与边界

当前会话没有 execution_bus 工具，桌面配置未安装本插件。本次由当前会话运行测试命令，在独立进程中加载本仓库编译产物及真实 DSH npm 组件；不修改日常配置、不热注入运行宿主、不重启 DSH。

这能验证真实 AgentLoop、SessionStore、ToolRuntime、Job 与 read 组件路径；不等于本会话实际调用 execution_bus，不验证真实桌面 UI、PTC 进程或真实模型。真实 AgentLoop 测试使用脚本模型适配器，read 组件测试使用测试 Agent 身份。两条测试不能合称当前会话端到端通过。

## 重复运行

1. npm ci --include=dev --ignore-scripts
2. npm run test:flow：流程回归、真实宿主执行组件、真实 AgentLoop 原调用结果关联。
3. npm run check：包含核心队列、安全和发布门禁的全部测试。
4. npm run verify:package：包白名单。

流程包括：正常成功/失败、读文件、权限拒绝、匿名请求拒绝、重复请求只新增一个 Job、工具取消、插件关闭、进度不作为聊天消息、原调用只提交一次后才继续下一模型适配器请求。

## 本次可复现问题

| 问题 | 修复前证据 | 本地修复 | 影响范围 |
|---|---|---|---|
| core 返回的 done 结果对象共享且可修改 | 第一个消费者将 state/result 改写后，第二次同请求取得被修改值 | 深度冻结终态快照 | core 扩展接入；不能据此声称模型能修改宿主冻结结果 |
| Handler 完成但结果 JSON.stringify 抛错被记为 failed | 返回 BigInt 的一次执行被误记 failed | 保存异常为 unknown / RESULT_NOT_RETAINED，不重跑 | 当前内置只读/测试返回值正常；扩展 Handler 有风险 |
| 结果超期查询未检查 TTL | 无新 request 时，过期 result 仍可读 | command 查询前 sweep | 查询/重取/取消均遵守结果保存期 |

三个测试在修复前均失败；修复后全量 24/24 通过。这些修复归入 0.1.1 补丁发布；不改变已有 0.1.0 标签或公开包。发布状态以 GitHub Release 和 npm 公开结果为准。

## 优化建议

1. 已优化：终态结果不可变；保存失败明确区分执行失败；查询触发 TTL 回收，无常驻清理定时器。
2. 后续可优化：完成请求重取无需新建短暂 Job；现在不会重复执行，但会产生不必要的 UI 生命周期事件。
3. 后续可优化：每个重复附着仍注册一个空进度监听器；可将进度观察者绑定到共享逻辑请求，避免消耗 32 个监听者限额。
4. 后续可优化：宿主 read 取消错误仍统一映射 HOST_READ_FAILED，保守归为 unknown。应保留经过白名单验证的取消类型，而不泄露原始异常文本。
5. 不建议盲目改动：取消一个附着工具会请求取消整个逻辑执行，是当前明确语义；改成仅取消等待者需要单独设计宿主 drain、Job 通知和结果留存，不能只 Promise.race 后抛弃原执行。

## 真实当前会话测试前提

只有宿主通过正常插件加载向当前 Agent 注册工具后，才可能真正执行 await tools.execution_bus。当前没有暴露可用的临时插件注册工具，不能用额外 Node 进程、伪造 sessionId 或追加聊天结果来替代。若后续要测试真实当前会话，需要另行授权安装/加载并确认工具可见；本次未执行安装。
